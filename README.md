# huan-app

独立 macOS 桌面应用，左侧导航切换阅读和翻译，左下角打开全局设置。基础阅读与 AI 独立；已实现本地收藏、原页容器、分平台会话策略、Readability 页面缓存、Pi SDK + DeepSeek 工具式伴读、YouTube 字幕阅读，以及 Qwen3.5-4B 本地离线中英互译。字幕获取使用官方 REST API，自动检测原语言并在提交前预检费用。

## 开发与验证

开发需要 macOS、Node 24.16.0、pnpm 10.12.1；首次安装需要下载 Electron。最终用户不需要 Node 或 pnpm。

```sh
nvm use
corepack enable
corepack prepare pnpm@10.12.1 --activate
pnpm install --frozen-lockfile
pnpm dev
# 退出开发应用后执行
pnpm check
pnpm pack:arm64
```

产物：`release/mac-arm64/huan-app.app`。Intel 使用 `pnpm pack:x64`，需真机另行验收。当前未签名、未公证，不用于公开发行。图标使用已确认的原设计 `build/icon.png`，由 electron-builder 转换为 macOS 图标资源。

当前不引入自动化测试框架。`pnpm check` 仅执行类型检查、Lint 和生产构建；运行行为通过每步人工 Review 验证。

`pnpm build` 仅生成 `out/`。`pnpm pack:arm64` 先执行 build，再由 electron-builder 按 `electron-builder.yml` 将编译结果、运行依赖、Electron 和图标打包到 `release/mac-arm64/huan-app.app`。`--dir` 只生成应用包，不生成 DMG/ZIP，也不自动复制到桌面。

生产模式加载 `app://ui/index.html`，不依赖开发服务器或 huan-cli。主进程编译为 `out/main/index.js`，preload 为 `out/preload/index.js`。

## 工程边界

| 路径 | 职责 |
| --- | --- |
| `src/main/index.ts` | 应用启动入口 |
| `src/main/app` | 窗口、生命周期、资源协议与 IPC 安全 |
| `src/main/settings` | 配置加载、校验、原子保存与文件选择 IPC |
| `src/main/bookmarks` | Markdown 解析、来源读取与最近成功副本 |
| `src/main/browser` | 原生网页容器、导航、页面状态与受限 IPC |
| `src/main/subtitles` | 字幕服务费用预检、内存缓存、凭据隔离与受限 IPC |
| `src/main/translation` | 包外模型进程、单次本地翻译请求与取消 |
| `src/preload` | 暴露有限的 app、settings、bookmarks、browser、AI、subtitles 与 translation API |
| `src/renderer/src/app` | React 应用外壳 |
| `src/renderer/src/components` | 无业务状态的图标、按钮、输入、下拉、标签页与截断文本 |
| `src/renderer/src/features/settings` | 设置表单、草稿、保存与取消 |
| `src/renderer/src/features/bookmarks` | 收藏列表、搜索、平台筛选、全量滚动与折叠 |
| `src/renderer/src/features/reader` | 阅读工具栏、原生容器定位与失败占位 |
| `src/renderer/src/features/translation` | 翻译草稿、语言切换、提交、停止与结果展示 |
| `src/shared/contracts` | 按功能定义通信契约 |

后续模块与数据格式见 [实施约定](docs/implementation-plan.md)。不提前创建空模块、插件框架或通用服务层。

收藏卡片统一为左侧平台图标、右侧单行标题与 URL，超出省略并通过原生 tooltip 提供全文。共享控件由 props 驱动，来源卡片、会话卡片和阅读空状态留在对应功能模块；IPC 与业务状态不进入通用组件。

两侧分隔条支持拖拽与键盘左右方向键调宽（Home / End 到最小 / 最大宽度）：收藏栏 240–420px，AI 栏 280–520px，并为中间阅读区预留至少 320px。窗口空间不足时自动限制侧栏宽度；折叠再展开保留本次运行的宽度偏好，不写入设置。拖拽期间暂时隐藏原生网页，结束后按新布局恢复。

两侧收起按钮放在模块内部：收藏栏按钮位于搜索输入框左侧，伴读栏按钮位于 AI / 字幕 Tab 同行的最右侧，顶部标题栏不再提供侧栏按钮。收起后保留 52px 窄条与展开按钮，其宽度计入阅读区布局预算；收藏搜索、筛选和对话草稿仍保留。收藏栏较窄时平台筛选自动换行，避免挤压搜索框。

根目录 `tsconfig.json` 作为编辑器的项目入口，引用 Node 与 Web 两套配置。`src/renderer/src/env.d.ts` 统一声明 `window.huanApp`；声明只提供类型，实际对象由 preload 注入。

跨模块导入使用 `@shared/*`、`@main/*`、`@renderer/*`；同目录导入保留相对路径。别名同时在 TypeScript 与 electron-vite 中配置，不能用来替代 `join()` 中的文件系统路径。IPC 通道统一定义在 `src/shared/ipc-channels.ts`，通过 `IPC_CHANNELS.browser.select` 等常量引用；参数类型保留在 contracts，来源校验与处理函数保留在对应功能模块。

## 数据与 Review

正常启动使用 `~/.huan-app/`。配置保存至 `~/.huan-app/settings.json`，支持 X、Reddit、YouTube、微信文章和 Other 五个来源，首次无配置时均停用；旧配置缺少微信或 Other 时默认停用、使用内存会话。Other 用于其他网站链接，沿用相同收藏表格，在设置中选择并启用对应 Markdown 文件，不猜测本机路径。启动读取启用来源，保存设置仅重读变更来源；关窗再打开不重读，不定时扫描。选中收藏后加载远程网页并按支持范围在本机提取正文，不自动发起 AI 请求或标记已读。

最近成功的解析结果保存在 `~/.huan-app/bookmarks/last-success.json`。解析保留原文件行顺序，跨文件按 X、Reddit、YouTube、微信、Other 拼接，以平台 + URL 去重保留第一次。列表在搜索和平台筛选后按采集日期（YYYY-MM-DD）倒序展示，按天显示居中日期分隔线；同日保留原顺序，缺失或无效日期统一归入末尾“日期未知”。采集日期不代表平台实际收藏时间，排序不改动原笔记。空链接、格式无效或非安全 HTTP(S) 链接的记录直接跳过，不影响其他收藏读取，也不删除原记录；表格结构错误仍会报错。成功读取反映源端删除；有效空表清空对应来源。失败仅使用同一路径的有效副本，并明确提示，来源路径变更后不会挪用旧路径的数据。停用来源不展示，但不删除其已有副本。

收藏表格在原有“采集日期”“标题 / 列表文字”“来源”“帖子链接”四列后增加“是否已读”，填写“是 / 否”；旧四列表格及空值视为未读，也接受“已读 / 未读”。卡片右侧勾选框手动切换：勾选为已读，取消为未读，打开帖子不会自动标记。仅该操作写回原笔记；首次修改旧表格时补列，保留其他单元格、表外内容和换行。重复 URL 的记录一起更新。写入前重读并做乐观冲突检查，同目录临时文件原子替换；这不是跨应用文件锁，仍应避免与 Obsidian 同时编辑。使用缓存副本时禁止修改；原文件成功而副本更新失败会单独提示，不回退已提交状态。

列表支持标题/链接搜索、平台筛选、全量滚动展示、折叠和选择，不再分页。搜索与平台筛选位于同一行，空列表仅显示浅绿色书签图标，底部不显示来源状态；读取异常仍在应用顶部提示。这些界面状态保留在本轮运行中，退出后重置。搜索与折叠不改变选中项，刷新后条目不再存在则回空状态，不自动选中其他帖子。选中收藏通过 WebContentsView 加载原页，支持前进/后退、刷新/停止；切换其他收藏后返回会重新加载原始 URL。页面内跳转不会改变选中收藏。

Review：打开左下角设置，为平台选择符合收藏表格格式（兼容旧四列）的 Markdown 文件并启用；保存后点击收藏阅读原页。原页无应用 preload，不可调用文件或设置接口。下载、非 HTTP/HTTPS 主页面导航、权限请求和 POST 弹窗暂不支持，不保证各平台第三方登录流程兼容。当前记录见 [A5/A6 验收](docs/a5-a6-review.md)，历史清单见 [A4](docs/a4-review.md)、[A2/A3](docs/a2-a3-review.md) 与 [A1](docs/a1-review.md)。

## 本地离线翻译

翻译页手动选择英语→中文或中文→英语，点击翻译或按 `Cmd+Enter` 提交，普通 Enter 换行。每次是独立的非流式本地请求，只显示最终译文，不接入伴读 Agent、工具、云端或自动重试。交换语言时仅将完整译文回填到原文，不自动提交；支持清空、复制和停止。切离翻译页停止当前请求，返回保留本轮草稿；阅读组件和原生网页不重建，聊天草稿、选中收藏及栏宽保持。翻译草稿和结果不写盘。

原文与译文区域随窗口剩余空间展开。翻译期间原文仍可聚焦、选取和编辑，语言切换与新提交继续保持单请求约束；修改原文后丢弃该请求的迟到译文，并提示重新翻译，即使又改回相同文字也不接纳旧结果。编辑不会自动取消或重新提交，需点击停止或等待当前请求结束。

直接引用既有 Qwen3.5-4B Q4_K_M GGUF 和 llama.cpp b11429 `llama-server`。开发态默认从工程同级 `../model` 加载，应用界面加载完成后在后台启动并加载模型，后续驻留，不等待首次翻译才启动。预热不阻塞界面；尚未就绪时提交翻译会等待同一次启动，不创建重复进程。后台启动失败通过翻译页显示原始错误，不自动重试；下次手动翻译仍可重新启动。关窗只隐藏，`Cmd+Q` 清理本应用启动的模型进程。模型内存占用提前到应用启动后，即使未使用翻译也会驻留。可通过环境变量覆盖包外绝对路径，不新增模型设置页：

```sh
HUAN_MODEL_PATH=/Users/bytedance/Desktop/llm/model/models/Qwen3.5-4B-Q4_K_M.gguf \
HUAN_LLAMA_SERVER_PATH=/Users/bytedance/Desktop/llm/model/runtime/llama/llama-b11429/llama-server \
pnpm dev
```

保留 runtime 目录中的配套动态库，不只复制单个可执行文件。权重和 runtime 均在工程之外，不增加到打包配置。打包态没有开发默认路径，需由启动环境显式传入两条路径；Finder 启动通常不继承终端变量，因此当前仅完成开发态验收，不宣称打包后已可开箱即用。

本地服务仅监听 `127.0.0.1` 随机端口，使用每次启动的新认证令牌，路径和令牌不暴露给 renderer。不开 Web UI、不下载模型、不继承其他 llama 参数或云端 Key。不主动输出原文/译文日志，原生诊断只在内存中保存并在失败时显示。

不设置输入字符、输出 token 或翻译等待时长的应用级上限；空白内容不提交。保持引擎默认上下文适配，输出 `n_predict=-1`，禁用上下文静默滑移。HTTP/模型错误原样显示；引擎若因上下文容量结束生成，会明确标记译文不完整，而非伪装成功。模型上下文、llama.cpp 原生超时、系统内存仍有限，超长输入可能报错、耗时很久或耗尽资源；取消仅丢弃译文，不保证释放驻留模型内存。首次模型启动另有 60 秒健康检查保护。

开发态实机记录与未验证边界见 [翻译验收](docs/translation-review.md)。此功能尚未将阅读区问答切换为本地模型，也未接入实时字幕翻译。

## AI 伴读

设置新增“AI 伴读”：内置唯一模型 DeepSeek Flash（`deepseek-flash`），固定官方 Chat Completions 端点。输入 API Key 后点击“保存设置”；不会读取 Pi CLI 认证、环境 Key 或用户扩展。Key 用 Electron safeStorage 加密保存为 `~/.huan-app/key-<UUID>.bin`，设置只保存引用。替换/清除 Key 不清空聊天，在途请求保留自身认证。未签名构建的 Keychain 行为需实机验证。

与字幕服务相同，DeepSeek Key 默认只展示掩码；点击眼睛才通过可信 IPC 读取当前保存值，隐藏、切换设置 tab 或关闭面板后清除展示明文。显隐不修改配置，不触发连接测试；留空保持保存值不变，清除仍需点击“清除 Key”并保存设置。

页面提取与 AI 独立：`page-host.ts` 监听完整导航和站内切页，加载后等待 1.5 秒，用 `readability.ts` 在隔离世界读取 DOM 副本；空结果每隔 1.5 秒重试，最多 4 次。中间视图关闭后台节流。X、Reddit 和微信仍限定文章详情页；Other 的 HTTP(S) 网站先检查文章可读性、排除带可见密码输入框的页面，再共用 Readability 提取正文，失败仍可浏览原页和普通聊天。预检兼容以 section/div 排版的结构化长文，仍交给 Readability 筛选，不回退到整页文本。YouTube 页面不提取，视频使用字幕链路。不下载图片、识别视频、自动滚动或抓取外链；Readability 是尽力识别，不能保证正文完整、排除所有评论或辨别全部敏感页面，发送前应核对当前阅读材料。提取仅在本机进行，只有提问并获既有材料授权后才允许 AI 按需读取冻结快照。

AI 来源 URL 移除片段，并按参数名净化查询字段；Other 仅保留常见文章定位参数 `id`、`p`、`page_id`、`post_id`、`article_id`、`story_id` 和 `lang`，值限 128 个 ASCII 字母、数字、下划线或连字符，不保留常见跟踪及授权字段。这不是敏感信息检测器，不能保证允许字段及路径中不含隐私信息。Other 的片段导航也重建快照，避免 hash 路由切换文章后沿用旧正文；但非常见查询参数或 hash 定位的站点，其净化后的来源链接可能不完整，应结合标题核对。原页和收藏 URL 不变。

Other 兼容已加载且显示的嵌入正文：主隔离世界采集 iframe 地址，读取 URL 与父页同源、可见 src 与 native 直接子 frame 唯一匹配的正文；不访问跨源 iframe、未显示标签页或未加载链接。Electron 子 frame API 不提供隔离世界执行接口，子 frame 使用固定页面世界闭包提取 DOM 副本，不改变 sandbox / Node / preload 权限；页面原型不可信，不能保证该降级采样不可篡改或无副作用，返回仍经格式及 frame 身份复核。应用不再限制 iframe 数量、标题或合并正文长度；总体提取等待仍最多 5 秒，省略标记截断。Other 每次提问前从当前 DOM 刷新本轮已冻结目录中的当前项，避免 URL 不变的标签页沿用旧正文；刷新纳入 AI 任务准备状态及停止流程，失败或切页时该项标为不可用，不补入新选页面。超时或停止后的迟到执行结果丢弃，不再启动后续 frame；已发出的 renderer JavaScript 无法强制取消。视频字幕仍在等待前同步冻结。

`page-store.ts` 在主进程保存页面快照，不再按页数淘汰或按标题、正文长度截断。每次有效导航创建独立页面 ID，异步结果需匹配导航才能入库。状态区分加载中、已提取、不可用和不支持；页面关闭清当前指针，退出清内存。不向日志输出提取的正文。缓存及每轮冻结快照会随材料累积占用更多内存，没有应用级容量兜底。

聊天固定为独立会话，切换收藏不重建组件或 Agent。每次发送时冻结页面快照，经版本 2 授权后传入本机 Worker；旧版仅当前页的授权不能代替新授权。DeepSeek 先收到页面目录，按需调用只读工具 `read_page` 获取正文片段；该工具只能读本轮快照，不访问文件、浏览器或网络。UI 显示工具实际读取的页面来源。无页面、读取失败或拒绝授权仍可正常聊天，模型不得猜测当前帖子；快照更新在下一次发送时生效。

视频材料需要版本 3 授权，包含当前视频元信息、已有字幕和冻结播放位置；授权版本只升不降。拒绝新增授权时保留已获授权的文章材料，普通聊天继续。字幕尚不可用时不会伪造正文，播放器位置未知时不附带秒数。

内置技能放在 `skills/<name>/SKILL.md`，在 `src/workers/ai/read-skill-tool.ts` 显式注册名称、描述和源码导入，通过 Vite `?raw` 随 Worker 打包，开发和生产使用同一份内容。模型先看到技能目录，再用 `read_skill({ name })` 按需加载全文；不扫描本机技能目录、不接受任意路径、不执行脚本。新增或修改技能需重新构建并重启应用。当前 `personal-notes` 基于本机个人笔记技能，已适配微信和阅读状态列（包含本机笔记库路径，调用时会随说明发送给 DeepSeek），不是自动同步链接；技能不授予权限，实际文件操作由显式注册的工具完成。系统提示仍要求每轮最多 8 次工具调用，但代码中的计数拦截目前已注释，不是强制上限。

Pi Agent Core / Pi AI / Pi Coding Agent 固定为 0.87.1，运行于按需启动的 utilityProcess，API Key 仅在当前请求期间引用。主进程不再限制会话数量、每会话请求/回合数量或全局并发数量，也不再在生成 180 秒后自动停止；同一会话仍不能同时执行多个请求。Worker 中工具次数、模型轮数及序列化上下文长度拦截目前已注释，不静默删除历史。尚存的限制包括输入 8,000 字符、read_page 每次最多返回 12,000 字符（通过 nextOffset 继续）、文件 read 的 Pi 分段/截断，以及每次输出 8,192 tokens；SDK 网络请求不自动重试。服务商实际上下文容量、限流及系统内存仍可能导致失败。

停止和新开对话沿用 Run 生命周期及实例隔离。停止等待 Worker 收尾，失败回合不写入模型历史；停止回合仅保留问题和部分文本，不留下孤立工具调用。若本轮已写入文件，失败或停止时额外保留真实保存回执，UI 不将已提交的文件误报为未保存；不会自动撤销写入。新开对话不清页面缓存或 API Key。消息以纯文本展示，不执行模型 HTML。退出不恢复历史；Worker 崩溃后保留 UI 记录，但需要新开对话。连接测试可能计费，不发送页面内容。

静态检查或成功打包不代表真实网站正文提取、付费模型问答和停止已验收通过。

## YouTube 实时字幕

按 v2.2 技术方案 5.1 实现，仅支持当前浏览器实际 URL 为 HTTPS YouTube `/watch?v=<videoId>` 的页面，不以左侧收藏选择推断视频。右栏保留默认 AI 伴读，新增“实时字幕”Tab；两页持续挂载，切换不清空聊天草稿或重建 Agent。

设置新增“字幕服务”：Transcript Guru Key 经主进程确认视频 URL 发送及费用说明后，用 safeStorage 加密保存；默认只展示保存状态和掩码，点击眼睛按钮时通过可信 IPC 读取当前字幕 Key，隐藏、离开字幕设置或关闭面板后清除展示明文，不改动保存值。配置默认增加 `subtitles: { credentialId: null, consentVersion: 0 }`，兼容旧 settings v1。未保存或正在编辑 Key 时隐藏用量；调用官方余额及消耗接口，首次加载及刷新都有 loading 提示，显示可用/预留 credits、每月发放和近 30 日消耗。credits 不等于 API 调用次数，不伪造未公开的日/月调用配额，提供固定官方后台入口。

按用户后续确认移除新任务的总门禁，不接入 MCP。先调用免费 `POST /api/v1/jobs/estimate`，请求原语言自动检测（`language: auto`、`force_asr: false`）；只在 `db_hit` 或 `caption_youtube`、预估 0 credits、无需确认且足额时提交 `POST /api/v1/jobs`（`language: auto`）。收费、翻译和 ASR 路径不自动提交；已受理任务仅用 GET 续查同一 job，不重复创建。正文仅接受 `source=caption` 或 `extension_upload`（官方浏览器扩展提取后上传的 YouTube 字幕），保留服务实际来源，界面区分浏览器提取；拒绝翻译、ASR 和未知来源，不能以 db_hit 或 0 credits 单独证明原字幕。预估不是服务端费用锁定，实际计费仍以官方记录为准；不承诺通用 API 不会回退，不下载音视频。

主进程按视频管理最多 20 份内存字幕，同视频合并在途 Promise；迟到结果校验条目、控制器及凭据，切页不取消其他视频已发出的获取。保留可续查 job 和提交未知记录，只有确定未受理的提交才清除未知标记。更换 Key 会 abort 并等待旧请求收尾，不清聊天和成功正文；重新创建旧账户/未知任务需要确认。字幕正文和任务不写盘，完全退出或清除 YouTube 会话后清空。

已配置并授权字幕 Key 时，检测到当前 YouTube 视频正文开始播放即后台获取字幕，不必先切到“实时字幕”Tab；暂停、广告及不可用的播放器不触发预取。进入字幕 Tab 仍可主动获取，并复用后台在途请求或已完成缓存。后台失败保留现有错误，等待手动重试，不随播放采样循环请求或弹出重新创建任务的确认框；缺 Key 或未授权时不自动联网，播放中保存有效配置后可开始预取。免费费用预检和来源校验保持不变，后台获取仍可能消耗服务 API 调用配额。

播放器在固定隔离世界采样，完成后 250ms 再读，新鲜度 1s、watchdog 2s；导航及广告不沿用旧位置。有效字幕按最远播放位置渐进展开，回退不收回正文；采样不可用时全文手动阅读，恢复后保留已展开文本。手动回看或选文停止跟随，可显式恢复；时间戳定位仅修改当前视频时间，保持播放/暂停状态。复制按选区提取字幕原文，排除时间戳和控件。

每次 AI 发送同步冻结已有全文及位置，`read_subtitles` 每次最多返回 12,000 字符，可按 `nextOffset` 继续；系统提示仍要求与其他工具共用每轮 8 次调用预算，但计数拦截目前已注释。来源详情只在真实读取工具后显示，模型不得将字幕等同于已观测视频画面。Run 结束释放本轮格式化正文。

字幕 provider 不再限制段落总数、合计正文大小或 HTTP 响应大小；仍校验字幕来源、格式、视频身份及时间戳顺序，并保留网络超时及服务限流退避。超长响应会增加本机内存占用；字幕服务的 20 份缓存上限和工具分页限制尚未移除。

实现和当前实机验收边界见 [5.1 Review](docs/subtitles-review.md)，不以静态检查或模拟结果代替真实字幕成功链路。

## AI 笔记读写

每回合在对话中显示实际装配的工具名单；加载失败显示具体错误，不将“目录已配置”等同于“工具可用”。本轮名单同时传给模型，避免沿用旧回合的不可用结论。`read` 只读取具体文件，不支持列举目录。

在设置的 AI 伴读页填写 Obsidian 笔记库绝对路径，保存并确认授权后生效；留空关闭。读取的 Markdown 会进入 DeepSeek 上下文，不会自动上传整个笔记库。下一轮根据最新配置装配工具，已经进入对话的内容需新开对话才能清除本机上下文。

保留现有 Agent Core 会话，复用 `pi-coding-agent` 的 `createReadTool/createWriteTool/createEditTool`；未切换到 `createAgentSession`，也未加载其默认配置、会话持久化、扩展或 Bash。文件 I/O 是现有主进程约定的一处明确例外：在 Node utilityProcess 的 `note-tools.ts` 中执行，主进程负责授权及原生确认。

仅允许配置目录内非隐藏的 `.md/.markdown`，单文件不超过 64 KB；拒绝工具路径中的符号链接。`write` 仅新建，已有文件用 `read` 后 `edit`。每次提交仅确认目标路径，不展示笔记正文；路径显示最多 160 字符，过长时省略中间部分，不改变实际写入路径，用户确认后才写入；取消不写文件。新建不覆盖同名文件，更新在确认后重读原文做冲突检查，再原子替换。目录校验不是 OS 沙箱，冲突检查不是跨应用锁，勿在操作期间由其他程序替换目录或同时编辑目标文件。

可提问“将当前文章整理到 raw/文章标题.md，保留来源链接”。正文不足时应标注限制；没有文件搜索工具，不声称已完成全库去重。本地保存回执不代表 iCloud 已同步；模型回复失败或停止不撤销已经完成的文件写入。强制杀进程可能来不及返回回执，此时应先核对磁盘再重试。

## 登录与隐私

设置中的“登录与隐私”按平台提供“仅本次运行 / 重启后保留”。旧配置自动兼容为内存模式，不自动保存登录态。模式在本轮启动时固定，保存更改后需 Cmd+Q 完全退出重启（关窗不算）；不迁移两种模式间的 Cookie。切换至内存模式不会删除此前的持久会话，需要使用“清除会话”单独移除。

内存分区为 `huan-app-reader-<platform>`，持久分区为 `persist:huan-app-reader-<platform>`，数据目录为 `~/.huan-app/`。同平台页面复用，跨平台隔离，包括从该平台跳出的页面。登录按原站流程处理，应用不采集密码、不导入系统浏览器 Cookie，不提供账号切换；即使保存会话，平台仍可能要求重新验证。

清除操作需要原生确认，取消不改数据；确认后先关闭当前受影响网页，再清除该平台内存与持久分区的网站数据、缓存和 HTTP 认证缓存。清除期间导航串行等待，避免页面重新写回数据。选中收藏保留，点击刷新重新加载；其他平台及收藏副本不受影响。此操作不代表注销服务器上的账号会话。

每步暂停等待用户 Review。测试证据见 [A0 记录](docs/a0-review.md)，旧 S0 记录仅保留为历史。
